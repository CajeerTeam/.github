# Projects

Cajeer keeps the public surface selective on purpose.

A project must earn its place: it should solve a real problem, keep its boundaries clear, and remain understandable after the first release cycle.

## Current public lanes

### Developer tools
Libraries and utilities for people who want more control, less ambiguity, and fewer unsafe shortcuts.

### Safe runtime logic
Public work such as **SafExpr** points toward a direction that values safe evaluation, explicit boundaries, and type-aware developer experience.

### Documentation systems
Documentation should feel like part of the product, not an afterthought attached later.

### Community infrastructure
Channels, release notes, and support surfaces should route attention cleanly and stay usable under growth.

## Portfolio posture

- fewer projects
- higher threshold
- clearer maintenance expectations
- stronger documentation discipline

Not everything needs to be public.  
What becomes public should hold up.
